# 实战案例

## 案例 1：机器人远程监控面板

**需求：**
```
帮我做一个完整的项目：机器人远程监控面板。
FastAPI 后端 + WebSocket 实时推送 + Vue3 前端。
支持多设备接入，显示电机状态、IMU 数据、电池电量。
带 Docker 部署。
```

**AI 自动完成：**

| Phase | 产出 |
|-------|------|
| Plan | 拆出 12 个 todo：后端框架、WebSocket 服务、设备管理、前端脚手架、实时图表、Docker... |
| 并行调研 | 子 Agent 1 查 FastAPI WebSocket 最佳实践；子 Agent 2 查 Vue3 实时图表库；子 Agent 3 查类似开源项目 |
| 实施 | 写完 23 个文件：`main.py`、`ws_manager.py`、`devices.py`、`App.vue`、`DeviceCard.vue`... |
| 验证 | ReadLints 发现 3 个类型错误 → 自动修 → pytest 42 个测试全过（覆盖率 84%） |
| 交付 | Dockerfile + docker-compose + CI + README（含架构图） |

**耗时：** 约 25 分钟（全自动）
**验收：** `docker compose up` → 打开浏览器看到实时数据流 ✅

## 案例 2：企业内部工具

**需求：**
```
做一个完整的后端服务：员工请假审批系统。
FastAPI + PostgreSQL + JWT 认证。
支持：提交申请、多级审批、邮件通知、审批历史查询。
要 80% 测试覆盖，带 CI/CD。
```

**关键决策（AI 自己定的）：**

| 决策点 | AI 选择 | 理由（写进了交付文档） |
|--------|---------|----------------------|
| 认证方式 | JWT + refresh token | 无状态，适合水平扩展 |
| 审批流建模 | 状态机（enum + 转换表） | 比 if-else 清晰，加节点容易 |
| 邮件 | Celery 异步队列 | 避免阻塞请求 |
| 测试 | pytest + factory_boy | 造数据快，测试可维护 |

**交付物：** 34 个文件，67 个测试，GitHub Actions 三条流水线。

## 案例 3：数据管道

**需求：**
```
完整的项目：从多个传感器采集数据，清洗后存到时序数据库，
提供查询 API 和 Grafana 面板。
```

**AI 的并行探索发现了什么：**

- 子 Agent 1 调研发现：InfluxDB 比 TimescaleDB 更适合高频写入
- 子 Agent 2 调研发现：传感器数据有乱序问题，需要 watermark 机制
- 子 Agent 3 找到了类似的 GitHub 项目，参考了它的批处理策略

**结果：** 避免了两个技术选型坑，交付即生产可用。

## 共同规律

三个案例都遵循同样的模式：

```
模糊需求 → AI 拆解并做技术决策 → 自动实施 → 自我验证 → 交付
```

**用户全程只做了一件事：说需求 + 最后验收。**
